1. 本次完成了什么

创建 Python 功能包，编写发布节点和订阅节点，通过 command 话题发送字符串 backup，并在 RQT 中观察节点连接。

当前订阅代码只计算并打印速度，没有发布速度消息，也没有控制真实电机。日志中的“发送速度”只是文字描述。

2. 功能包、文件和节点的区别

概念 本次实例 作用
工作空间 learning_ws 组织源码与构建结果
功能包 example_topic_rclpy 管理代码、依赖和运行入口
Python 文件 topic_publisher_02.py 保存源代码
Python 类 NodePublisher02 定义节点的属性和行为
ROS2 节点 topic_publisher_02 程序运行时创建的通信参与者

消息类型 std_msgs/msg/String 规定消息结构，字符串放在 data 字段

ros2 pkg create 创建包的结构，touch 创建空文件。只有运行程序并执行节点构造代码，才会创建运行中的节点。

教程前面的节点代码是基础框架，后面的代码为同一个类增加发布、订阅和回调功能。合并时保留导入和 main()，替换原来的类定义，不能把两个同名类直接叠在一起。

3. 节点基础代码怎样执行

  • 第一行用于直接执行脚本时选择 Python 3 解释器。
  • rclpy 是 ROS2 的 Python 客户端库。
  • Node 提供节点名称、日志、发布订阅、定时器等能力。
  • class ... (Node)：继承 Node。
  • __init__：创建对象时自动执行的初始化方法。
  • self：当前对象，由 Python 自动传入。
  • name：传入的节点名称。
  • super().__init__(name)：完成父类 Node 的初始化。
  • get_logger().info(...)：输出普通信息日志，问候只在初始化时打印一次。

执行顺序：初始化 ROS2 → 创建节点 → spin 处理回调 → 退出运行环境。

spin() 会等待并处理订阅、定时器等回调，不会重复执行 __init__。按 Ctrl+C 可能抛出 KeyboardInterrupt，因此例子里最后的 shutdown() 不保证执行到；后续可学习异常处理和资源清理。

args 是什么

args 是 arguments 的缩写，是普通变量名，不是 Python 关键字。本例用于向 ROS2 传入启动参数。

6. setup.py 运行入口

格式：命令名称 = Python包.模块:函数。ros2 run 用左边的命令名找到右边的 main()。

依赖方面：代码使用 rclpy 和 std_msgs，功能包的 package.xml 应声明这两个依赖。当前创建命令仅声明了 rclpy，后续应补上 <depend>std_msgs</depend>，方便其他环境安装依赖。

问候由订阅节点自身的 __init__ 打印，即使发布者没有启动也会出现。真正收到消息后，才会执行订阅回调并打印“收到[backup]”。

10. 本次遇到的问题与修复

10.1 找不到生成的功能包

最初包生成在 /home/linx/example_topic_rclpy。教程的 cd chapt3/chapt3_ws/src/ 是相对路径，目录不存在时切换失败，下一行创建命令仍可能执行。

现在包已移动到 learning_ws 的 src 下，无需再次移动或重新创建。

执行创建操作前先确认当前目录；可用 cd 目标目录 && 下一条命令，保证切换成功后再执行。

10.2 NameError: name ‘String’ is not defined

两个节点都使用了 String，但没有导入。修复：

Python 区分大小写：String、string、STRING 是不同名称。

10.3 回调写到了类外

timer_callback 和 command_callback 原来与 class 顶格，未成为类的方法。修复时将整个方法缩进到类内。

类方法通常缩进 4 个空格，方法体再缩进 4 个空格。

10.4 发布器变量名不一致

创建时使用 self.command_publisher，调用时却使用 self.command_publisher_。末尾下划线也是变量名的一部分，必须统一。

本次统一为 self.command_publisher。

10.5 验证结果

修复后指定包构建成功。两个节点同时运行时，订阅端连续收到了 backup 消息；RQT 截图也显示了发布节点经 /command 连接到订阅节点。

11. 后续练习

  • 把定时周期从 0.5 秒改成 1 秒，观察接收频率。
  • 修改发送字符串，观察订阅回调的分支变化。
  • 给发布回调添加日志，区分“发布”和“收到”。
  • 停止发布者，观察订阅者是否仍然运行。
  • 修改一个节点的话题名称，观察通信和 RQT 图的变化。
  • 补齐 package.xml 中的 std_msgs 依赖。
  • 学习 try/finally、destroy_node 和关闭上下文的处理。
  • 下一步学习服务通信，对比 Topic 与 Service。
